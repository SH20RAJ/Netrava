# Security Policy

## 1. Security Philosophy

Netrava is engineered for mission-critical public safety and government surveillance infrastructure. Because government video networks involve sensitive public infrastructure and citizen privacy, security and auditability are non-negotiable architectural requirements.

Netrava enforces:
1. **Zero Trust Network Architecture**: Internal service communication requires mutual authentication and token verification.
2. **Immutable Audit Trails**: Every search, video stream access, camera modification, and evidence export records an immutable audit log entry including actor identity, role, timestamp, source IP, and query scope.
3. **Cryptographic Chain-of-Custody**: All evidence frames and video clips generated by AI events compute SHA-256 integrity hashes upon creation to guarantee tamper-evident provenance.
4. **Role-Based Access Control (RBAC)**: Granular permissions partitioned across 7 roles (`SUPER_ADMIN`, `STATE_ADMIN`, `DISTRICT_ADMIN`, `CONTROL_ROOM_OPERATOR`, `INVESTIGATOR`, `ANALYST`, `AUDITOR`).
5. **No Embedded Credentials**: Camera passwords, stream tokens, database credentials, and signing secrets are managed strictly through environment secrets or vault abstractions.

---

## 2. Reporting a Vulnerability

If you discover a security vulnerability within Netrava, please do **NOT** file a public GitHub issue.

Please report vulnerabilities directly via:
- **Email**: `security@netrava.gov.in` (or repository security contact)
- **Response SLA**: 24 hours acknowledgment, 72 hours initial assessment.

Please include:
- Affected component or service (e.g. Stream Gateway, API, Auth)
- Step-by-step reproduction instructions or proof-of-concept
- Potential impact and severity assessment

---

## 3. Data Privacy & Governance Principles

Netrava strictly follows purpose-based data governance:
- **Configurable Retention**: Video feeds remain in local/regional ring buffers with automated purging (default 7-30 days).
- **Redaction Pipeline**: Capability to mask sensitive bystander regions or non-target entities.
- **Statutory Compliance**: Conformance with the Information Technology Act (2000), Digital Personal Data Protection (DPDP) Act (2023), and MoRTH CCTV guidelines.
